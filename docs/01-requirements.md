# TaskFlow: Requirements (ฉบับร่าง v0.2)

สถานะ: **รออนุมัติ** | โปรเจกต์: Task and Project Tracker | Stack: Go + React + PostgreSQL

## 1. เป้าหมาย
เว็บแอปสำหรับทีมเล็ก ใช้สร้างโปรเจกต์ แตกเป็นงาน มอบหมายคนรับผิดชอบ และติดตามสถานะบนบอร์ด Kanban

## 2. ผู้ใช้
| บทบาท | สิทธิ์ |
|---|---|
| **Owner** (ผู้สร้างโปรเจกต์) | จัดการโปรเจกต์ทั้งหมด เพิ่ม/ลบสมาชิก ลบโปรเจกต์ |
| **Member** | ดูโปรเจกต์ สร้าง/แก้/ย้ายงานในโปรเจกต์ที่เป็นสมาชิก |
| ผู้ที่ไม่ใช่สมาชิก | มองไม่เห็นโปรเจกต์นั้นเลย (ได้ 404) |

## 3. User Story (MVP)
เกณฑ์การรับงาน (AC) ต้องตรวจได้ด้วย test

### Auth
- **US-01** ในฐานะผู้ใช้ ฉันสมัครสมาชิกด้วยอีเมลและรหัสผ่านได้
  - AC: อีเมลซ้ำได้ 409; รหัสผ่านสั้นกว่า 8 ตัวได้ 422; รหัสผ่านถูกเก็บแบบ hash (argon2/bcrypt) ไม่เก็บ plain text
- **US-02** ในฐานะผู้ใช้ ฉันเข้าสู่ระบบแล้วได้ JWT
  - AC: อีเมล/รหัสผ่านผิดได้ 401 ข้อความเดียวกันทั้งสองกรณี; token หมดอายุภายใน 60 นาที
- **US-03** ในฐานะผู้ใช้ ฉันดูข้อมูลตัวเองได้ (`GET /me`)

### Project
- **US-04** สร้างโปรเจกต์ → ฉันเป็น Owner อัตโนมัติ
- **US-05** เห็นรายการเฉพาะโปรเจกต์ที่ฉันเป็นสมาชิก
  - AC: ผู้ใช้ B เปิดโปรเจกต์ของ A ที่ B ไม่ได้เป็นสมาชิก ได้ 404
- **US-06** Owner แก้ชื่อ/คำอธิบาย และลบโปรเจกต์ได้ (soft delete เก็บ 30 วัน กู้คืนได้ ตามกติกาข้อ 3.1)
  - AC: โปรเจกต์ที่ถูกลบหายจากรายการปกติ และงานในโปรเจกต์นั้นเข้าถึงไม่ได้ จนกว่าจะกู้คืน
- **US-07** Owner เพิ่ม/ลบสมาชิกด้วยอีเมลได้; Owner ลบตัวเองไม่ได้

### Task
- **US-08** สมาชิกสร้างงานในโปรเจกต์ (ชื่อ, คำอธิบาย, priority, วันครบกำหนด, ผู้รับผิดชอบ)
  - AC: ผู้รับผิดชอบต้องเป็นสมาชิกโปรเจกต์นั้น มิฉะนั้นได้ 422
- **US-09** ดูบอร์ดแบ่งคอลัมน์ `todo / in_progress / review / on_hold / done` เรียงตามตำแหน่ง
- **US-10** ย้ายงานข้ามคอลัมน์และเรียงลำดับใหม่ (drag-and-drop)
- **US-11** แก้ไขงานได้
- **US-12** กรองงานตามผู้รับผิดชอบ สถานะ priority และค้นหาด้วยข้อความในชื่องาน

### ถังขยะ (Soft delete และกู้คืน)
- **US-13** สมาชิกลบงาน → งานย้ายไป "ถังขยะ" ของโปรเจกต์ ไม่ถูกลบจริง
  - AC: งานหายจากบอร์ดและผลค้นหาทันที; บันทึกเวลาลบ (`deleted_at`) และผู้ลบ (`deleted_by`)
- **US-14** สมาชิกดูรายการในถังขยะและเห็นจำนวนวันที่เหลือก่อนถูกลบถาวร
- **US-15** สมาชิกกู้คืนงานจากถังขยะได้ภายใน 30 วัน
  - AC: งานกลับมาอยู่คอลัมน์และตำแหน่งเดิม; ผู้รับผิดชอบที่ไม่ได้เป็นสมาชิกแล้วจะไม่อยู่ในงาน ส่วนคนอื่นยังอยู่ตามเดิม; กู้คืนเกิน 30 วันได้ 404
- **US-16** ระบบลบถาวรอัตโนมัติเมื่อครบ 30 วันนับจาก `deleted_at`
  - AC: งานเบื้องหลังรันวันละครั้ง; ลบเฉพาะแถวที่ `deleted_at < now() - 30 วัน`; มี log จำนวนที่ลบ; ทดสอบด้วย test ที่ควบคุมเวลาได้

### ธีมและภาษา
- **US-17** สลับโหมด **สว่าง / มืด** ได้ (มีสองโหมดเท่านั้น ไม่มี "ตามระบบ" ตามที่ผู้ใช้สั่ง 2026-11-06)
  - AC: จำค่าที่เลือกข้ามการรีเฟรช; **ครั้งแรกที่เปิด** (ยังไม่เคยเลือก) เริ่มจากโหมดที่ตรงกับอุปกรณ์ แล้วค่าที่ผู้ใช้เลือกมีผลเหนือกว่าเสมอ; ไม่กระพริบสีผิดโหมดตอนโหลดหน้า; ทุกหน้าอ่านออกในทั้งสองโหมด (contrast ข้อความ ≥ 4.5:1)
  - หมายเหตุ: ฝั่ง backend (ตาราง users, API `/me`) ยังรับค่า `system` อยู่ จะจัดให้เหลือ light/dark ตอนเชื่อมการตั้งค่ากับบัญชี (ชุดงาน B)
- **US-18** สลับภาษา UI **ไทย / อังกฤษ** ได้ทันทีโดยไม่ต้องรีเฟรช
  - AC: ข้อความทุกจุดมาจากไฟล์แปล (ไม่ฝังในโค้ด); ข้อความ error จาก API แสดงตามภาษาที่เลือก; วันที่และตัวเลขจัดรูปแบบตามภาษา; จำค่าที่เลือก
- **US-19** การตั้งค่าธีมและภาษาผูกกับบัญชี (ล็อกอินเครื่องอื่นได้ค่าเดิม)

### 3.1 กติกาถังขยะ (ใช้กับงานและโปรเจกต์)
| หัวข้อ | กติกา |
|---|---|
| ระยะเก็บ | 30 วันนับจาก `deleted_at` (ตั้งเป็นค่า config `TRASH_RETENTION_DAYS=30`) |
| กู้คืนงาน | สมาชิกทุกคนของโปรเจกต์ |
| กู้คืนโปรเจกต์ | Owner เท่านั้น (งานในโปรเจกต์กลับมาทั้งหมดตามสถานะเดิม) |
| ลบโปรเจกต์ | งานในโปรเจกต์ไม่ถูกทำเครื่องหมายลบทีละใบ แต่ซ่อนตามโปรเจกต์ |
| ลบถาวรด้วยมือ | ไม่มีใน MVP (รอครบ 30 วันเท่านั้น) |
| งานที่ถูกลบ | ห้ามแก้ไข/ย้าย/มอบหมาย ต้องกู้คืนก่อน (ได้ 404) |
| หลังลบถาวร | กู้คืนไม่ได้ ตัดความสัมพันธ์ที่เกี่ยวข้องออกให้เรียบร้อย |

> หมายเหตุ: ร่างก่อนหน้าให้ลบงานถาวร คุณเลือก soft delete จึงปรับให้ทั้งงานและโปรเจกต์ใช้กติกาเดียวกัน หากต้องการให้โปรเจกต์ต่างจากงาน บอกได้

## 4. Non-functional
| ด้าน | เกณฑ์ |
|---|---|
| ความปลอดภัย | ทุก endpoint ยกเว้น register/login/health ต้องมี JWT; เช็กสมาชิกภาพทุกครั้งใน service layer; ใช้ parameterized query; CORS จำกัด origin |
| ประสิทธิภาพ | endpoint รายการตอบ p95 < 300 ms ที่ 10,000 งาน; list ใช้ pagination |
| คุณภาพ | coverage ≥ 70% (backend), CI ผ่านจึง merge ได้ |
| การออกแบบภาพ | **โทนสีพาสเทล** เป็นเอกลักษณ์ของแอป; มีชุดสีสำหรับโหมดสว่างและมืด (พาสเทลโทนอ่อนบนพื้นสว่าง, พาสเทลหม่นบนพื้นมืด) กำหนดเป็น design token (CSS variables) จุดเดียว ห้ามฝังสีในคอมโพเนนต์ |
| การเข้าถึง | contrast ข้อความ ≥ 4.5:1 ทั้งสองโหมด (พาสเทลมักอ่านยาก ต้องตรวจจริง); สถานะงานต้องไม่แยกด้วยสีอย่างเดียว (มีไอคอน/ป้ายข้อความประกอบ); ใช้งานด้วยคีย์บอร์ดได้ |
| หลายภาษา | ไทย/อังกฤษ ผ่านระบบ i18n (react-i18next) ไฟล์แปลแยกต่อภาษา; ภาษาเริ่มต้นตามเบราว์เซอร์; API ส่ง **error code** ให้ frontend แปล ไม่ส่งข้อความภาษาเดียว |
| ข้อมูล | ข้อมูลที่ถูกลบเก็บ 30 วันแล้วลบถาวรอัตโนมัติ (ดูข้อ 3.1); การลบถาวรต้องไม่กระทบข้อมูลที่ยังใช้งาน |
| การใช้งาน | responsive รองรับจอมือถือ |
| การสังเกตการณ์ | structured log (JSON), `/health`, error tracking ด้วย Sentry (Phase หลัง) |

## 5. นอกขอบเขต MVP (ทำภายหลัง)
คอมเมนต์ในงาน, แนบไฟล์, แจ้งเตือนอีเมล, real-time sync, refresh token, ลืมรหัสผ่าน, OAuth/SSO, หลาย workspace

## 6. การตัดสินใจแล้ว
| เรื่อง | ข้อสรุป |
|---|---|
| ภาษา UI | สลับไทย/อังกฤษได้ (US-18) |
| ธีม | พาสเทล สลับสว่าง/มืดได้ (US-17) |
| การลบ | soft delete เก็บ 30 วัน กู้คืนได้ แล้วลบถาวรอัตโนมัติ (US-13 ถึง US-16) |

## 7. คำถามเปิดที่เหลือ
1. ต้องการบทบาทมากกว่า Owner/Member หรือไม่ (เช่น Viewer) ถ้าไม่ตอบ ใช้ Owner/Member ตามร่าง
2. โปรเจกต์ใช้กติกาถังขยะเดียวกับงานตามข้อ 3.1 ถูกต้องหรือไม่
3. ต้องการให้ Member กู้คืนงานได้ทุกคน หรือเฉพาะผู้ที่ลบ/Owner
